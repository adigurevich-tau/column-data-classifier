Data tagging · CSV column classifier

Column Classification Rules

A deterministic, rule-based tool that examines CSV columns and assigns one of seven data categories, or leaves a column unclassified.

Overview

Approach

  1. Exclude null-like values (e.g., empty strings, N/A, and None).
  2. Evaluate each column against all seven classifiers. Each classifier applies two types of checks:
    • Mandatory checks – verify that values meet the basic requirements of a category.
    • Supplementary checks – provide additional evidence supporting the classification.
  3. Assign a single classification only if at least 95% of non-null values pass the mandatory checks and at least 5% pass the supplementary checks, with at least one supplementary match.
  4. If multiple classifiers qualify, select the one with the strongest match rates.

Other options considered

  1. Score individual checks: Assign a score to each supplementary check and average the scores to produce an overall result.
  2. Group related categories: Identify groups of potentially related categories (e.g., date types) and classify columns only within the relevant group.
  3. Expand categories: Add more categories beyond US state to help distinguish columns that might otherwise receive an incorrect classification.
  4. Use column names: Lower classification thresholds when the column name provides supporting evidence for a category.
  5. Use cross-column context: Adapt checks based on values in other columns—for example, validate phone numbers against US formats when the country or city indicates the US.

What Works Well / What Does Not Work Well

What Works Well

  • SSN, email, and close-list categories such as US states are the easiest to detect reliably.

What Does Not Work Well

  1. Free-text columns: These are the hardest to classify because they lack unique mandatory checks and cannot easily be compared against a predefined list without a large reference database.
  2. Birth dates: They can be confused with other date columns, such as ages or start dates. Defining reliable rules is difficult because valid age ranges depend on the population represented in the dataset.
  3. Thresholds: Current thresholds are based on intuition and limited testing. They need to be validated across different datasets, considering factors such as missing values and spelling consistency.

With More Time

  1. Tune thresholds: Test multiple datasets and analyze score distributions to set more reliable thresholds.
  2. Expand the supplementary reference lists: Add more representative values and examples to the reference files to improve coverage and recognition across different datasets.
  3. Add more classifiers: Expand the number of supported categories to improve coverage.
  4. Expand reference databases: Build larger example datasets for comparison.
  5. Test against known labels: Evaluate the classifier on datasets with known column types to identify additional failure cases.
  6. Improve code efficiency: Refactor and optimize the implementation to reduce unnecessary work, improve performance, and make the code easier to maintain.

How classification works

Each non-empty cell is checked against each detector. A column receives a category only when it meets both the mandatory and supplemental requirements.

Mandatory threshold

At least 95%

At least 95% of non-empty values in the column must pass that category's mandatory detector.

Supplemental threshold

At least 5% and at least one match

At least one value must also provide supplemental evidence, and the supplemental match rate must be at least 5%.

Categories are checked in the order shown by the rules below. If multiple categories pass, the classifier selects the one with the highest mandatory match rate, then the highest supplemental match rate. The check order resolves any remaining tie.

Rules for each category

1. National ID (US SSN)

Mandatory checks

  • A string or a whole number greater than or equal to zero, containing exactly nine digits.
  • Digits are contiguous or grouped 3-2-4 with consistent hyphens or spaces.
  • Area is not 000, 666, or 900–999; group is not 00; serial is not 0000.

Supplemental checks

  • Standard 3-2-4 separator format.
  • Area number is at or below 772. This is a supplemental hint only, not a validity rule.
2. Email Address

Mandatory checks

  • Exactly one @, with non-empty local and domain parts.
  • No whitespace or invalid characters; local part does not start/end with a dot or contain consecutive dots.
  • Domain has at least two non-empty labels; labels do not begin or end with a hyphen.

Supplemental checks

  • Top-level domain is alphabetic and at least two letters long.
3. Phone Number

Mandatory checks

  • A string or a whole number greater than or equal to zero; the main phone number contains 7–15 digits.
  • Main number uses only digits, spaces, hyphens, parentheses, and an optional + at the beginning.
  • Optional extension formats: x3819, ext 3819, ext. 3819, or extension 3819. Extension has 1–6 digits and is excluded from the main-number digit count.
  • Date-shaped values are rejected; plus signs may appear only once and only at the beginning.

Supplemental checks

  • Starts with + or 00 (international-prefix hint), or matches the recognized US-style format.
4. Date of Birth

Mandatory checks

  • An actual calendar date in YYYY-MM-DD, DD/MM/YYYY, MM/DD/YYYY, or DD-MM-YYYY format.
  • Invalid calendar dates and unsupported formats do not pass.

Supplemental checks

  • Age implied by the date is between 0 and 120, inclusive; or the header is one of dob, date_of_birth, birth_date, birthdate, date_birth.
  • Known non-DOB headers (including start_date, hire_date, termination_date, end_date, created_at, updated_at, and joining_date) block DOB classification.
5. US State

Mandatory checks

  • Value is either a two-letter abbreviation or a one-to-three-word alphabetic name format.
  • Matching is case-insensitive; leading or trailing whitespace is not accepted.

Supplemental checks

  • Value matches a recognized US state name or USPS two-letter abbreviation in the data/us_states.txt reference list.
7. City

Mandatory checks

  • One to four words; starts with a letter and has at least two characters.
  • Only letters, spaces, periods, and apostrophes are allowed.
  • Capitalization is all uppercase, all lowercase, or title case.

Supplemental checks

  • Value matches an entry in the editable data/cities.txt reference list.
7. Person Name

Mandatory checks

  • String with 1–5 words, using letters, spaces, hyphens, apostrophes, or periods.
  • No leading/trailing whitespace or repeated spaces; capitalization is all uppercase, all lowercase, or title case.
  • Supports given-name-first and surname-first formats, such as Rosella Burks and Burks, Rosella.

Supplemental checks

  • Both first-name and surname components match the reference dictionaries; or the value uses the accepted surname-first comma format.

How to run the classifier

Clone the repository and open a terminal in the project directory.

git clone https://github.com/adigurevich-tau/column-data-classifier.git
cd column-data-classifier
python3 main.py

The program asks for the CSV file path. You can also pass the path directly:

python3 main.py sample_employees.csv
python3 main.py sample_employees.csv --verbose
python3 main.py sample_employees.csv --json

Tests

python3 -m unittest discover -s tests -v

Generated HTML report and privacy

After a successful analysis, the program writes a standalone report beside the source CSV. For example, sample_employees.csv produces sample_employees_report.html.

  • Summary cards show total columns, classified columns, unclassified columns, and rows evaluated.
  • A collapsible column summary lists each column name and its assigned tag.
  • Individual column cards show category, confidence, mandatory and supplemental match rates, non-empty row count, explanation, and expandable candidate checks.
  • The report does not include CSV cell values or sample records.
  • The original CSV is read locally and is not modified or uploaded by the program.

No third-party Python packages are required; the project uses the Python standard library.
