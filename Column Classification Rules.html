Data tagging · CSV column classifier

Column Classification Rules

A deterministic, rule-based tool that examines CSV columns and assigns one of eight data categories, or leaves a column unclassified.

How classification works

Each non-empty cell is checked against each detector. A column receives a category only when it meets both the mandatory and supplemental requirements.

Mandatory threshold

At least 95%

At least 95% of non-empty values in the column must pass that category's mandatory detector.

Supplemental threshold

At least 5% and at least one match

At least one value must also provide supplemental evidence, and the supplemental match rate must be at least 5%.

Supplemental evidence by category

Detector order

  1. National ID (US SSN)
  2. Email Address
  3. Phone Number
  4. Date of Birth
  5. US State
  6. Employment Position
  7. City
  8. Person Name

Specific categories run before broader categories such as City and Person Name. If multiple categories pass, the classifier selects the one with the highest mandatory match rate, then the highest supplemental match rate. Detector order resolves a remaining tie.

Rules for each category

1. National ID (US SSN)
  • Accepts a string or non-negative integer containing exactly nine digits.
  • Digits may be contiguous or grouped 3-2-4 with consistent hyphens or spaces.
  • Area cannot be 000, 666, or 900–999; group cannot be 00; serial cannot be 0000.
  • The 772 area limit is supplemental only.
2. Email Address
  • Requires exactly one @ and non-empty local and domain parts.
  • No whitespace, leading/trailing dot or consecutive dots in the local part.
  • Domain must have at least two non-empty labels; labels cannot begin or end with a hyphen.
  • A conventional alphabetic TLD is supplemental evidence. No DNS or mailbox check is performed.
3. Phone Number
  • Accepts strings or non-negative integers. Main number must contain 7–15 digits.
  • Allowed main-number characters are digits, spaces, hyphens, parentheses, and an optional + at the beginning.
  • Recognizes optional extensions written as x3819, ext 3819, ext. 3819, or extension 3819. Extension length is 1–6 digits and is not counted as part of the main number.
  • Date-shaped strings are explicitly rejected to reduce confusion with date columns.
  • Recognizes US-style formatting as supplemental evidence; a prefix beginning + or 00 is also supplemental evidence.
  • Formatting checks do not establish that a number is assigned or reachable.
4. Date of Birth
  • Accepts actual calendar dates in YYYY-MM-DD, DD/MM/YYYY, MM/DD/YYYY, or DD-MM-YYYY format.
  • Supplemental evidence is a plausible age from 0 to 120, or a recognized DOB header: dob, date_of_birth, birth_date, birthdate, date_birth.
  • Known non-DOB date headers such as start_date, hire_date, termination_date, end_date, created_at, and updated_at block DOB classification.
5. US State
  • Matches a US state name or USPS two-letter abbreviation, case-insensitively.
  • The editable reference list is data/us_states.txt.
6. Employment Position
  • Matches a normalized job title from the editable reference list.
  • Normalization ignores case and treats punctuation or other separators as spaces.
  • The reference list is data/employment_positions.txt.
7. City
  • Must start with a letter and contain 1–4 words.
  • Allowed characters are letters, spaces, periods, and apostrophes.
  • Must be all uppercase, all lowercase, or title case.
  • Matching data/cities.txt provides supplemental evidence.
8. Person Name
  • Accepts 1–5 words made from letters, spaces, hyphens, apostrophes, and periods.
  • Must have consistent uppercase, lowercase, or title case; leading/trailing or repeated spaces are rejected.
  • Rejects placeholders such as Unknown, Anonymous, N/A, and Test User.
  • Supports both given-name-first and surname-first forms, including Burks, Rosella.
  • First-name and surname reference lists provide supplemental evidence.
Important: The classifier identifies values that fit defined patterns and reference data. It does not prove that a value is genuine, belongs to a particular person, or is currently in use.

Run the classifier

Clone the repository and open a terminal in the project directory.

git clone https://github.com/adigurevich-tau/column-data-classifier.git
cd column-data-classifier
python3 main.py

The program asks for the CSV file path. You can also pass the path directly:

python3 main.py sample_employees.csv
python3 main.py sample_employees.csv --verbose
python3 main.py sample_employees.csv --json

To inspect all rows instead of the default maximum of 100,000:

python3 main.py sample_employees.csv --max-rows 0

Tests

python3 -m unittest discover -s tests -v

Generated HTML report and privacy

After a successful analysis, the program writes a standalone report beside the source CSV. For example, sample_employees.csv produces sample_employees_report.html.

  • Summary cards show total columns, classified columns, unclassified columns, and rows evaluated.
  • A collapsible column summary lists each column name and its assigned tag.
  • Individual column cards show category, confidence, mandatory and supplemental match rates, non-empty row count, explanation, and expandable candidate checks.
  • The report does not include CSV cell values or sample records.
  • The original CSV is read locally and is not modified or uploaded by the program.

No third-party Python packages are required; the project uses the Python standard library.
